# 취업 가이드 작성 규격 (v2, 2026-10-08)

`client/content/guides/*.md`에 올라가는 글의 규격. 발행 예약 작업과 사람이 같이 본다.
글감은 `.agents/guide-backlog.md`. 잘 쓴 예: `motivation-question-structure.md`, `job-competency-question.md`, `teamwork-experience-question.md`.

v1(09-19)의 고정 뼈대("채용 담당자가 ○○에서 확인하는 것 → 구조 → 예시로 보는 차이 → 자주 하는 실수")는 글마다 똑같아 AI가 쓴 글처럼 읽혔다. 10-06부터 아래 방식으로 바꿨다.

## 0. 절대 규칙

- **검수 없이 발행하지 않는다.** 초안은 `codex/guide-<slug>` 브랜치 PR로만 올리고, 머지는 창업자가 한다.
- **실제 기록으로만 쓴다.** 근거는 창업자의 커피챗·멘토링·모의면접 기록과 본인 취준 기록뿐이다. 소재 파일은 저장소 밖(로컬, gitignore)에 있다: `.agents/threads/notion-mining/_merged.md`(맨 먼저 §5 "쓰면 안 되는 것"을 읽는다), `own-jobhunt.md`, `coffeechat-logging.md` 등, `.agents/threads-material-pool.md`. 기록에 없는 일화·숫자·인용을 만들지 않는다.
- **지어낸 예시 문장 금지.** "전/후" 예시 자소서를 꾸며 쓰지 않는다. 틀이 필요하면 `○○` 빈칸으로 보여 준다.
- **멘티 이야기를 창업자 1인칭으로 쓰지 않는다.** "커피챗에서 만난 분", "멘토링에서 본 자소서"처럼 익명으로. 멘티 자소서 문장은 원문 인용 금지.
- **회사가 드러나는 내부 정보 금지.** 사업부 이익 구조, 면접 평가 방식, 채용 인원 같은 것. 창업자가 지원자로서 공개적으로 겪은 면접(받은 질문)은 써도 된다.
- **타깃은 신입 공채 지원자뿐.** 이직·경력직·경력기술서·커리어 전환·중고신입 금지(테스트가 막는다).
- **점수·퍼센트·합격 보장 금지.** "합격률", "○점", "붙는 자소서" 금지.

## 1. frontmatter (테스트: `client/src/lib/guides.test.ts`)

```
title: 50자 이내. 목표 검색어를 앞에, 관점을 뒤에
description: 30~110자. 본문 첫 문장과 겹치지 않게
category: 자소서 | 면접 후기          (이 두 값만)
coverStyle: chat | quote | plain | mark
coverLabel: 작은 분류 줄(예: 자소서 문항 · 커피챗 기록)
coverQuestion: 커버 큰 글씨. 두 줄, 줄바꿈은 \n
coverAnswer: 커버 답 줄. 일반 글은 두 줄(\n), 면접 후기는 한 줄
coverTone: hyundai | samsung       (면접 후기만, 회사 색)
coverLogo: /guide/logos/<회사>-white.svg   (면접 후기만)
date: 발행일(YYYY-MM-DD)   updated: 고친 날
keywords: 목표 검색어 1 + 변형 3~4 (쉼표 구분)
```

- 파일 이름이 곧 slug다(소문자-케밥, 영어).
- **coverStyle은 목록에서 바로 옆 글과 겹치면 안 된다**(테스트가 막는다). 목록은 date 최신순이니, 새 글이 맨 앞에 오면 지금 맨 앞 글의 coverStyle과 다른 것을 고른다.
- **커버 문구는 "~라면", "~였을까"로만 끝내지 않는다.** 명사형("○○하는 포부", "채용 담당자의 첫 10초")을 섞는다. 답 줄의 숫자·내용은 본문에 있는 것만.

## 2. 본문 (1,300~2,500자)

정해진 뼈대가 없다. 대신 이것만 지킨다.

1. **장면이나 실제 질문으로 시작한다.** 커피챗에서 받은 질문, 면접 연습에서 자주 나온 한 문장, 창업자가 겪은 일. 첫 두세 문장 안에 "이 글이 무엇에 답하는지"가 보이게.
2. **소제목은 글마다 다르게.** 아래 제목은 쓰지 않는다: "채용 담당자가 ○○에서 확인하는 것", "예시로 보는 차이", "자주 하는 실수", "내 ○○은 …인가", "정리".
3. **처방은 순서나 기준으로.** 창업자가 실제로 그려 준 순서(예: 다섯 줄 순서)는 번호 목록으로, 빈칸은 `○○`.
4. **근거를 문장 안에 밝힌다.** "커피챗에서 열네 번 넘게 한 말", "제가 본 ○○ 1차 면접에서" 처럼 어디서 나온 이야기인지.
5. **끝은 `---` 아래 두 문단.** ① 경험→초안: `Pre:View [내 경험](/my)에 해 본 일을 먼저 적어 두세요…경험에 없는 숫자는 지어내지 않고 빈칸으로 남겨요.` ② 분석: `…[자소서 분석](/analyze)에서 확인할 수 있어요. 첫 분석은 무료예요.` 글 주제에 맞게 한 구절씩만 바꾼다.

## 3. 문장

- **해요체, 1인칭(저).** 창업자가 커피챗에서 말하듯. 한 문단 2~4문장. 문단 안에서 줄바꿈하지 않는다(`breaks: true`).
- 짧은 문장과 긴 문장을 섞는다. 모든 문장이 "~입니다/~해요"로 같은 길이면 AI처럼 읽힌다.
- 쓰지 않는 표현: "다양한", "효과적으로", "체계적으로", "~을 통해", "~의 중요성", "시너지", "역량을 함양", "끊임없이", "이러한", "정리합니다". (`ai-written-resume-tells` 글의 12가지가 그대로 금지어다.)
- 굵은 글씨는 한 글에 한두 곳.
- 독자를 가르치지 않는다. "~해야 합니다"보다 "~하면 읽는 사람이 ~로 읽어요".

## 4. 근거로 쓸 수 있는 관찰 (기록에서 반복된 것, 익명 요약)

자세한 원문·출처는 로컬 소재 파일에 있다. 아래는 요약이라 이것만으로 일화를 지어내지 않는다.

- 다섯 줄 순서: 직무가 하는 일 → 필요한 역량 → 나에게 있다 → 경험이 근거 → 들어가서 할 일. 커피챗·멘토링에서 가장 자주 그려 준 순서.
- 직무를 내 말로 다시 정의하면 무관해 보이던 경험이 산다.
- 경험 라이브러리: 경험을 표로 나열하고 300/500/800자 버전을 만들어 두면 문항마다 새로 쓰지 않는다. 회사마다 새로 쓰는 건 지원동기 정도.
- 한 문항에 경험 대여섯 개 + 숫자만 → 어떤 사람인지 남지 않는다. 한 문항엔 경험 하나, 많아야 둘.
- 소제목에 역량 이름을 쓰면 소제목·본문·결론이 따로 논다.
- 숫자 한 줄은 면접 질문 한 줄이 된다("실제로 몇 명이었나요?").
- 여러 직무 사람들과 일해 본 경험은 기획·마케팅에서 거의 매번 어필하라고 한 것. 권한을 키워 쓰면 면접관은 안다.
- 지원동기는 회사 칭찬에서 끝내지 말 것 — 회사가 잘하는 것 → 요즘 시장 → 내가 해 본 쪽 → 들어가서 할 일.
- 흔한 고민: 내 경험이 이 직무에 통하나(전공·직무 전환), 경험을 고르지 못하고 나열함, 매번 새로 써서 오래 걸림, 연속 탈락 뒤 불안.

## 5. 검수 요청(PR 본문) 양식

```
목표 검색어: …
이 글의 주장 한 줄: …
근거 기록: (문단마다 어느 기록에서 왔는지 — 파일 이름과 항목 번호. 멘토링 원문은 PR에 붙이지 않는다)
커버: coverStyle … / 큰 글씨 … / 답 줄 …
검수 체크: □ 기록에 없는 사실·숫자 없음 □ 멘티 이야기를 1인칭으로 쓰지 않음 □ 회사 내부 정보 없음 □ 고정 뼈대 소제목 없음 □ 커버 문구가 본문과 맞음
```
