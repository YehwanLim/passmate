# 취업 가이드 작성 규격

`client/content/guides/*.md`에 올라가는 글의 규격. 발행 루틴과 사람이 같이 본다.
글감은 `.agents/guide-backlog.md`, 경험담 소재는 `.agents/guide-material/`.

## 0. 절대 규칙

- **검수 없이 발행하지 않는다.** 초안은 `codex/guide-<slug>` 브랜치 PR로만 올리고, 머지는 창업자가 한다.
- **타깃은 신입 공채 지원자뿐.** 이직·경력직·경력기술서·커리어 전환·중고신입 이야기는 쓰지 않는다(테스트가 막는다).
- **점수·퍼센트·합격 보장을 말하지 않는다.** "합격률", "○점", "붙는 자소서" 금지. 말할 수 있는 건 "읽는 사람이 무엇을 보는가"다.
- **지어낸 경험담 금지.** 면접 후기·경험담은 `.agents/guide-material/`에 창업자가 넣은 메모가 있을 때만 쓴다.
- **예시 문장은 가상이라고 PR에 밝힌다.** 본문에는 표시하지 않고, PR 본문 "가상 사례" 목록에 전부 적는다.
- **기업 글은 공식 채용 페이지의 공개 문항만.** 출처 링크와 "2026 하반기 기준"을 본문에 적는다. 내부 평가 기준·합격 스펙 추측 금지.

## 1. frontmatter (테스트: `client/src/lib/guides.test.ts`)

```
title: 50자 이내. 목표 검색어를 앞에, 관점을 뒤에
description: 30~110자. 검색어 + 이 글이 주는 것 2~3가지
category: 문항별 | 상황별 | 기업별 | 직무별 | AI 활용 | 면접 준비 | 면접 후기 | 첫인상 | 수정하기
date: 발행일(YYYY-MM-DD)   updated: 고친 날
keywords: 목표 검색어 1 + 변형 3~4 (쉼표 구분)
```

파일 이름이 곧 slug다(소문자-케밥, 영어). frontmatter `slug:`로 바꾸지 않는다(본문 로더가 파일 이름으로 찾는다).

## 2. 본문 구조 (1,800~3,000자)

1. **첫 문단** — 검색한 질문에 바로 답한다. 흔한 오답 → 이 문항이 실제로 묻는 것(굵게 1~2곳). AI 검색·스니펫이 인용하는 자리다.
2. **`## 채용 담당자가 ○○에서 확인하는 것`** — 번호 목록 3~4개.
3. **`## 쓰는 법 / 고르는 기준 / 구조`** — 순서가 있으면 번호, 없으면 불릿. 비중(2할·3할)을 적으면 따라 쓰기 쉽다.
4. **`## 예시로 보는 차이`** — 같은 소재의 전/후 인용문 1쌍 + "읽는 사람이 얻는 정보:" 해설. 전 예시는 흔한 문장, 후 예시는 숫자·행동·판단이 있는 문장.
5. **`## 자주 하는 실수`** — 굵은 한 문장 + 이유 한두 문장, 4~5개.
6. **`## 내 ○○은 …인가`** — 스스로 판단하기 어려운 이유 → Pre:View가 짚어 주는 것(리포트 항목 이름 그대로: 첫인상, 문장별 진단, 예상 면접 질문, 채용공고 맞춤) → `[…진단받기](/analyze) — 첫 분석은 무료입니다.` + 관련 가이드 링크.

내부 링크는 글마다 **가이드 2개 이상**(같은 분류 1, 다른 분류 1) + `/analyze` + 필요하면 `/report-new?sample=1`, `/company-report?sample=1`.

## 3. 문장

- 합니다체. 한 문단 3~5문장. 문단 안에서 줄바꿈하지 않는다(`breaks: true`라 `<br>`이 된다).
- 주장 → 이유 → 예. 형용사·부사 대신 행동과 숫자.
- 쓰지 않는 표현: "다양한", "효과적으로", "체계적으로", "~을 통해", "~의 중요성", "시너지", "역량을 함양", "끊임없이", "이러한". (`ai-written-resume-tells` 글의 12가지가 그대로 금지어다.)
- 독자를 가르치지 않는다. "~해야 합니다"보다 "~하면 읽는 사람이 ~로 읽습니다".
- 멘토링에서 반복된 관찰을 근거로 쓴다(아래 4). 통계·연구를 지어내지 않는다.

## 4. 근거로 쓸 수 있는 관찰 (멘토링·면접 기록에서 반복된 것, 익명)

- 4단 논리: 직무가 하는 일 → 필요한 역량 → 내가 가진 근거 → 들어가서 할 일.
- 경험 라이브러리: 경험을 표로 나열하고 키워드를 붙여 두면 문항마다 새로 쓰지 않는다. 재탕이 안 되는 문항(지원동기)에만 시간을 쓴다.
- 자소서 뼈대: 문항의 핵심 질문에 답하는 요약 문장 1개 → 경험 제목 → 경험 내용.
- 한 문장 포지셔닝: 경험이 많은데 정리가 안 되는 사람은 "여러 개를 다 잘하는 사람"으로 읽혀 기억에 남지 않는다.
- 기사 읽기: 회사 기사는 회사가 뿌린 가이드다. 최근 기사에서 회사가 힘주는 사업과 단어를 가져온다.
- 직무 밖 경험도 근거다. 산업 경험이 없어도 역량 구조가 같으면 엮을 수 있다.
- 성과가 없어도 된다, 신입이니까. 어떤 논리로 진행했고 내 역할이 무엇이었는지가 남는다.
- 부풀린 경험일수록 꼬리 질문이 온다. 한 줄로 쓴 경험까지 "그건 뭐 한 거예요?"가 나온다.
- 흔한 고민: 연속 탈락 뒤 자존감, 너무 가고 싶은 회사 앞에서 작아지는 마음, 전공과 다른 직무 지원 불안, 자소서 한 편에 며칠씩 걸림.

## 5. 검수 요청(PR 본문) 양식

```
목표 검색어: …
이 글의 주장 한 줄: …
가상 사례: (예시 문장·숫자 전부)
출처: (기업 글이면 채용 페이지 URL·확인일)
검수 체크: □ 사실과 다른 주장 없음 □ 진부한 문단 없음 □ 예시가 그럴듯함 □ 제목이 검색어로 읽힘 □ 제품 연결이 과하지 않음
```
