# 네이버 블로그 채용 공고 글 규격

블로그 `blog.naver.com/815lyw` 분류 **Career** 에 올리는 신입·인턴 채용 공고 글의 규격. 루틴과 사람이 같이 본다.
설계: `docs/superpowers/specs/2026-09-25-naver-blog-job-posting-routine-design.md`. 대장: `ledger.md`. 초안: `drafts/`.

**기준 글**: 신세계그룹 2027 신입 공채(2026-09-27 발행, logNo 224423447705). 사용자가 직접 손본 글이라 이 글의 톤·서식이 정본이다.
아래 규격은 2026-09-27 에 그 발행본을 읽고 다시 썼다. 이전 판(합니다체·1인칭 금지·본문 해시태그)은 폐기.

## 0. 절대 규칙

- **발행 버튼은 사용자가 누른다.** 루틴은 `scripts/naver-blog.sh post` 로 임시저장까지만.
- **공식 채용 페이지 원문으로 확인한 정보만 쓴다.** 접수 시각·직무·자격·문항은 2차 출처(사람인·기사)만으로 쓰지 않는다. 원문을 못 열면 그 회사는 뺀다.
- **공고 전문을 복사하지 않는다.** 요약 + 출처. 자소서 문항은 원문 그대로 인용(짧다). 공고 이미지·포스터는 쓰지 않는다. 회사 로고는 직접 만든 커버 안에 작게 넣는 것만 된다(2026-09-30 사용자 요청, §6 커버 규격).
- **타깃은 신입·인턴 지원자.** 경력직·이직·경력기술서 이야기는 쓰지 않는다.
- **합격 스펙·경쟁률·합격률 추측, 점수·퍼센트 금지.** "채용 담당자가 무엇을 보는가"만 말한다.
- **경험담을 지어내지 않는다.** 취준 경험·면접 경험을 없는데 있는 것처럼 쓰지 않는다.
  단 마무리의 1인칭 서비스 이야기(커피챗 100회, Pre:View 를 직접 만들었다, 내 자소서로 돌려봤다)는 **사실이므로 쓴다**(§3-7). 이 블로그의 면접 후기 글들과 같은 사람의 목소리로 읽혀야 한다.

## 1. 초안 파일 형식 (`drafts/YYYY-MM-DD-<slug>.md`)

```
1행: 제목
2행: (빈 줄)
3행~: 본문. 한 행 = 편집기의 한 줄(Enter). 빈 행 = 빈 줄 하나(여러 개면 여러 줄 띄움).
  "## 소제목"  → 편집기 소제목 서식(큰 글씨) + 굵게. 스크립트가 굵게까지 넣는다
  "---"        → 구분선(수평선). 섹션 사이를 나눈다
  "> 문장"     → 인용구 박스. **자소서 문항 원문 한 줄**에 쓴다(문항당 1개, 보통 3개)
  "**문장**"   → 한 줄 굵게 + **16pt**(스크립트가 넣음, 2026-10-03). 핵심 정보의 라벨 줄(접수 기간 등)과 묶음 소제목((1) 영업 등)에.
                 본문 줄 바로 뒤에 오면 스크립트가 앞 빈 줄을 2개로 맞춘다(소제목 사이 엔터 두 번). ## 소제목·구분선 바로 뒤는 그대로
  "✍ / 💡 / 🚫 …" 줄 → 스크립트가 굵게(크기 13 그대로) 넣는다(2026-10-03 사용자 요청). 초안에는 ** 없이 그대로 쓴다
  "http…"      → URL 한 줄만 두면 편집기가 링크 카드로 바꾼다
  마지막 행: "태그: 신세계그룹채용, 이마트채용, …"  ← 발행 창 태그 칸에 넣을 목록. **본문에 타이핑하지 않는다**
```
편집기에 실제 키 입력으로 들어가므로 위 표기 말고는 마크다운(|, -)을 쓰지 않는다. 이모지는 그대로 쓰면 된다.
**줄 머리에 "1. " 같은 "숫자+점+공백"을 쓰지 않는다** — 편집기가 자동 번호 목록으로 바꿔 다음 줄에 번호가 붙는다. 목록 번호는 ①②③, 문항은 "Q1."로 쓴다.

### 본문에 해시태그를 쓰지 않는다

검색에 걸리는 태그는 **발행 창의 "태그 편집" 칸**에 넣은 것만이다. 본문에 `#키워드` 를 적어도 그냥 글자다
(2026-09-27 확인: 현대자동차 면접 후기 글은 본문에 `#간절함` 이 있는데 태그 영역은 "작성된 태그가 없습니다").
그래서 태그는 본문에서 빼고 초안 마지막 줄 `태그:` 에 모아 둔다. 발행할 때 그 줄만 복사해 태그 칸에 붙인다.
**태그 6~9개.** 회사명+채용, 브랜드명+채용, 시즌, 신입공채, 자소서문항 계열로 섞는다.

## 2. 제목 공식 (60자 내, 검색어를 앞에)

- 단건: `{회사명} {연도} {시즌} 신입 공채 채용공고 | {마감·대표 브랜드·자소서 문항 중 핵심 2~3개}`
- 주간 모음: `{n}월 {몇째} 주 접수 중 신입 공채 모음 | 마감 순 정리 ({대표 회사 3~4곳} 등 {n}곳)`

**마감 시각과 검색량 큰 브랜드명은 제목에서 빼지 않는다.** "9월 30일 17시 마감", "CJ올리브영" 같은 말이 클릭을 만든다.

## 3. 단건 본문 순서 (1,500~2,500자, 해요체)

1. **첫 문단** — 누가·언제까지·무엇을 뽑는지 두세 줄. 이어서 이번 공채의 특징 한 가지를 "이번 공채에서 제일 눈에 띄는 건 ~" 식으로.
2. **이미지 1장** — 첫 문단 뒤. 목록 썸네일이 여기서 잡히므로 **없으면 안 된다**. 공고 캡처·포스터는 쓰지 않고, 직접 만든 커버(§6)를 쓴다.
3. `---` → `## 📌 핵심 정보` — 라벨 줄과 값 줄을 나눠 쓰고 항목 사이는 빈 줄 2개. **라벨 줄은 굵게.**
   ```
   **접수 기간**
   2026.9.18(금) ~ 10.12(월) 18:00
   ```
   접수 기간 / 참여 계열사 / 지원 자격 / 전형 절차 / 접수처.
4. `---` → `## 📝 자소서 문항 분석` — 한 줄 안내(글자 수 특징, 계열사별로 문항이 다르면 명시).
5. **문항별 분석**(글의 중심, 문항당 10~16줄). 문항마다:
   - `> Q1. 문항 원문 (글자 수)` — 인용구 박스
   - 바로 본문 2~3줄로 **무엇을 묻는 문항인지**. 라벨(👀) 없이 문장으로 시작한다.
   - `✍ 이렇게 써보세요` — 문단 구조와 비중("노력 60퍼, 이유 30퍼, 입사 후 10퍼"), 첫 문장에 무엇을 둘지.
   - `💡 넣을 수 있는 소재` — 신입이 실제로 가진 것(수업·프로젝트·아르바이트·매장 관찰·동아리 운영 숫자)을 직무별로 2~3개.
   - `🚫 이 내용은 피하세요` — 흔한 오답 1~2개와 그 이유.
6. `---` → `## ✅ 지원 전에 확인할 것` — 마감 시각, 중복 지원, 증빙, 테스트 등. 한 줄에 하나.
7. `---` → `## 마무리` — 순서를 지킨다.
   ① 이 글의 문항 하나를 골라 어디서 막히기 쉬운지 2~3줄.
   ② **1인칭 서비스 이야기** — 취준생과 커피챗을 100번 넘게 하며 본 패턴을 모아 서비스를 만들었다는 흐름. 무엇을 받아볼 수 있는지(문장별 피드백, 어떻게 읽히는지, 예상 면접 질문) 2~3줄.
   ③ 첫 분석 무료 + 피드백 주면 1회 분석권 추가. 내 자소서로 돌려보니 실제 면접 질문과 겹쳤다는 한 줄.
   ④ URL 한 줄 → 링크 카드.
   `https://pre-view.me/analyze?utm_source=naverblog&utm_medium=blog&utm_campaign=job-posting`
   **UTM 을 뗀 맨 주소(`https://pre-view.me/`)를 쓰지 않는다.** 떼면 관리자 대시보드에서 블로그 유입이 안 잡힌다.
8. **출처** — 채용 홈페이지 URL 한 줄만 둬서 링크 카드로 만든다. "출처:" 라는 글자는 없어도 된다.
9. `태그:` 줄(§1).

**직무 섹션은 선택.** 계열사별 직군 구조가 복잡해서 따로 설명할 값이 있을 때만 3~5 사이에 `##` 로 넣는다(예: 올리브영 31개 직무). 없으면 빼는 쪽이 글이 짧아서 낫다.

주간 모음: 첫 문단(기준일·원칙) → `■ 이번 주 마감` → `■ 다음 주 이후 마감` (① 회사 — 마감 시각. 직무·특징. 접수처) →
원문 미확인 회사는 괄호로 따로 → `■ 이번 주에 챙길 것` → `■ 마무리` → 출처 → `태그:`.

## 4. 문장 (2026-09-27, 신세계 발행본 기준)

- **해요체.** "~해보세요 / ~이에요 / ~같아요 / ~인데요". 정보 줄(접수 기간, 전형 절차, 사실 확인)은 "~입니다"로 끊어도 된다. **글 전체를 합니다체로 쓰지 않는다.**
- **한 글 안에서 톤이 갈리면 안 된다.** 첫 문단만 말랑하고 뒤가 딱딱한 게 제일 나쁘다.
- **단정 대신 제안.** "이렇게 쓰세요"보다 "이렇게 써보세요", "안전합니다"보다 "안전할 것 같아요", "중요합니다"보다 "중요해요 (당연)".
- **구어 표시를 허용한다.** 말줄임 `,,,`, 느낌표 `!`, "요렇게", "60퍼/30퍼/10퍼" 같은 입말. 과하면 안 되고 문단마다 한두 개.
- **한 줄이 길면 끊는다.** 한 행에 한 문장, 긴 문장은 쉼표 자리에서 줄을 바꾼다. 문단 사이는 빈 줄 1개, 섹션 사이는 구분선.
- **이모지는 소제목과 라벨 줄에.** 📌 📝 ✍ 💡 🚫 ✅ ⏰ 🛒 🕺 🙂 같은 것 한 글에 8~12개. 문장마다 붙이지 않는다.
  **변형 선택자(U+FE0F)가 붙는 이모지(✍️ ⚠️ ☑️ ❤️ ▶️ ☀️ 등)는 편집기에 두 번 찍히므로 쓰지 않는다.**
- 주장 → 이유 → 예. 형용사·부사 대신 행동과 숫자.
- 쓰지 않는 표현: "다양한", "효과적으로", "체계적으로", "~을 통해", "~의 중요성", "시너지", "역량을 함양", "끊임없이", "이러한".
- 독자를 가르치지 않는다. "~해야 해요"보다 "~하면 읽는 사람이 ~로 봐요".
- 마무리 안내는 글마다 다르게. 정형 문구 복사 금지.
- **따옴표는 작은따옴표(' ')만 쓴다**(2026-10-03 사용자 요청). 큰따옴표는 쓰지 않는다. 스크립트도 넣을 때 " 를 ' 로 바꾼다.
- **가운데점(·) 대신 슬래시(/)를 쓴다**(2026-09-27 사용자 요청). "계열사/직무", "서울/전주/대구/부산". 제목도 같다.
- **회사·브랜드 표기는 공식 표기로 통일한다.** 한 글 안에서 엇갈리지 않게(예: 신세계인터내셔**날** — "널" 아님).

## 5. 선정 기준 (루틴)

- 접수 중이거나 7일 내 시작, 마감 3일 이상 남음, 신입·인턴, 원문 확인됨, 대장에 없음.
- 우선순위: 대기업 그룹 공채 > 채용연계형 인턴 > 중견·스타트업 신입 > 체험형 인턴. 동률이면 검색량이 클 회사명.
- 없으면 쓰지 않고 알림만. 다른 형식으로 억지로 채우지 않는다.
- **주간 모음은 지금 쓰지 않는다**(2026-09-27 결정: 화·목·일 모두 단건). 아래 주간 모음 형식은
  나중에 되살릴 때를 위해 남겨 둔 것이고, 현재 루틴은 만들지 않는다.

## 6. 루틴이 아직 못 하는 것 (사람이 한다)

`---` 구분선과 `태그:` 줄은 2026-09-27 에 `scripts/naver-blog.sh` 가 지원하게 됐다(실기 확인).
아래는 아직 사람이 한다.

- 이미지 1장 → `post` 에는 아직 안 들어갔다. 2026-09-27 DB 글에서 손으로 한 번 성공한 방법:
  커버는 HTML 로 만들어 캡처(800×1000) → `covers/` 에 보관. 원본 HTML·로고는 `covers/src/` 에 둔다.
  **커버 규격(2026-10-01 사용자 확정)**: 틀은 `covers/src/2026-09-30-kis-fy2026.html`(한국투자증권) 그대로 쓰고 회사만 바꾼다.
  위에서부터 로고(작게) → 작은 분류 줄 → 회사명 크게 + 한 줄 부제 → 가로선 → 마감 일시 크게 → 직무/계열사 2열 목록 → 한 줄 특징.
  글씨는 Pretendard 만. 배경은 로고 대표색을 아주 연하게 **단색**으로, 제목은 로고색을 진하게, 마감일은 로고 대표색.
  예: 한국투자증권(로고 갈색 #682800) → 배경·제목·마감 모두 갈색 계열
      한화(로고 주황 #ed7100) → 배경 #ffe2c6, 제목 #3a1c04, 마감 #e86a00
  **내용은 가운데 800×800 안에만 둔다(2026-10-03 사용자 확인).** 모바일 블로그 목록은 4:5 커버를 정사각형으로 가운데만 보여 줘서 위아래 100px 씩 잘린다(로고가 잘렸음). body 를 세로 가운데 정렬로 두고 캡처 뒤 내용 위끝 ≥140px, 아래끝 ≤860px 인지 DOM 으로 잰다.
  **글마다 색이 확실히 달라야 한다**(10-01 사용자: "두 개 색깔이 거의 똑같다"). 단 **로고에 거의 안 보이는 색을 끌어오지 않는다**
  (10-01: 한국투자증권에 로고 속 작은 파란 획을 배경으로 썼다가 "한투 로고는 파란색이 아닌데"로 기각). 로고 주색이 직전 커버와 비슷하면
  같은 색 계열 안에서 밝기·채도로 가른다(예: 주황은 선명한 살구, 갈색은 회갈색/밀크티/크림 쪽).
  **쓰지 않는 것**: 그라데이션 배경, 알약 모양 강조 칸, 손글씨/명조 글씨, 달력/노트 같은 소품 구성(09-30~10-01 후보 8개에서 기각).
  로고는 공식 사이트나 위키미디어 공용의 투명 PNG/SVG 를 받는다. 포스터·공고 이미지를 잘라 쓰지 않는다.
  캡처는 `agent-browser --session cover` 로 연 뒤 `set viewport 800 1000` → `screenshot`. 헤드리스 크롬 `--screenshot` 은 이 맥에서 파일을 안 쓰고 멈춘다.
  **캡처가 끝나면 `agent-browser --session cover close` 로 꼭 닫는다.** 열어 두면 같은 앱 이름이라 편집기 창 활성화가 그쪽으로 가서 `post` 가 포커스를 못 잡는다(2026-10-01 실기).
  편집기 iframe 의 `HTMLInputElement.prototype.click` 을 가로채 파일 선택 창 대신 input 을 붙잡고,
  "사진 추가" 클릭 → JS 로 `DataTransfer` 에 File 을 넣어 `input.files` 설정 + `change` 발생.
  첫 이미지는 네이버가 자동으로 "대표"로 잡는다. `agent-browser upload` 는 iframe 안 input 을 못 잡는다.
- 발행 창 태그 입력 → 루틴은 발행 창을 열지 않으므로 항상 수동. 실행 끝에 복붙용 한 줄을 출력한다.

### 편집기를 자동으로 다룰 때 아는 것 (2026-09-27 실기)

- **"작성 중인 글이 있습니다" 복구 모달이 뜨면 키 입력이 전부 무시된다.** 이 모달은 편집기 iframe 안에 있어
  `agent-browser snapshot`(접근성 트리)에 **안 잡힌다**. 반드시 DOM 으로 찾아 "취소"를 눌러야 한다.
  제목·본문도 같은 이유로 접근성 트리에 없다. 확인은 전부 DOM(`ab eval`)으로 한다.
- 글쓰기 URL 을 바로 열면 편집기가 직전 문서를 그대로 물고 있다. 홈을 한 번 거쳐야 빈 글이 뜬다.
- `ab press <key> --repeat N` 은 플래그를 무시하고 1회만 누른다(exit 0). 반복은 `ab batch --bail "press X" …`.
- `Home`/`End`/`Shift+Home`/`Meta+Arrow` 는 캐럿을 못 옮긴다. 좌표 클릭과 ArrowLeft/Right 만 쓴다.
- 임시저장 목록에서 지금 편집기에 열려 있는 글은 "작성중"이라 체크박스가 비활성이다. 지우려면 먼저 편집기를 비운다.
- **이미 저장된 글 고치기(2026-10-03 실기).** 임시저장 목록 항목에는 제목 버튼(`button.article_button…`)과 삭제 버튼이 같이 있고, 삭제 버튼 라벨에도 제목이 들어 있다. 제목 텍스트로 찾아 누르면 삭제 확인창이 뜰 수 있으니 반드시 `article_button` 을 누른다(확인창은 `ab dialog dismiss`).
  JS 로 잡은 선택 영역과 마우스 드래그 선택은 편집기가 무시한다(입력이 글 맨 앞에 들어감, `Meta+z` 두 번으로 되돌림). 캐럿은 **좌표 클릭**(문단 끝 오른쪽)으로 두고, 지울 땐 Backspace, 고를 땐 `Shift+ArrowLeft` 를 `ab batch` 로 반복한다. 빈 문단에서 Backspace 를 누르면 그 뒤 키가 유실되니 줄 단위로 나눠 지운다.
  글자 크기는 상단 툴바(@ref)로는 안 먹고, 선택하면 뜨는 **떠 있는 작은 툴바**의 크기 칸을 좌표로 눌러야 적용된다.
  **키보드 없이(창 포커스 없이) 되는 방법(10-03 실기)**: 줄 가운데를 마우스 down/up 세 번(`ab batch`) → 줄 전체 선택 → iframe 안 `button.se-contents-toolbar-label-select-button`(font-size) 좌표 클릭 → `span.se-toolbar-option-label` 중 원하는 숫자 좌표 클릭. 좌표는 iframe rect + 요소 rect. 드래그 선택은 안 된다.
  글자 입력(keyboard type/inserttext)은 OS 창 포커스가 꼭 있어야 한다. 맨 앞 앱이 Claude 면 osascript activate 가 막히므로 사용자가 창을 한 번 띄워야 한다. 같은 글을 다시 저장하면 개수는 그대로고 목록 시각만 바뀐다.
- **`keyboard type` 직후에 누른 키는 유실된다.** 편집기가 입력을 반영하는 동안 들어온 키를 삼킨다.
  지연 없이 5회 시도해 5회 모두 실패했고, 타이핑 뒤 0.6초를 넣으니 3회 모두 성공했다. 타이핑 다음에
  방향키·Enter 로 캐럿을 옮겨야 하면 반드시 쉬었다 누른다.
- **인용구는 "인용문 + 출처" 두 칸짜리 컴포넌트다.** 그래서 두 가지를 조심한다.
  줄을 이을 때 Enter 를 누르면 캐럿이 출처 칸으로 넘어가므로 **Shift+Enter** 를 쓴다.
  박스를 빠져나올 때도 탈출에 실패하면 다음 문단이 통째로 출처 칸에 들어간다. 겉보기 글자만으로는
  본문인지 출처인지 구분이 안 되니, 확인은 `.se-quote` / `.se-cite` 로 나눠서 본다.
