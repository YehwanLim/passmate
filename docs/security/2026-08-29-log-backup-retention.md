# 로그·백업 보관 기간 정책

**작성일:** 2026-08-29
**관련:** `docs/security/2026-08-26-release-gate-checklist.md` 7번 항목
**개인정보 처리방침:** `client/src/pages/Privacy.tsx` (3조 보관 기간, 2026-08-29 개정)

## 원칙

- 사용자 데이터는 서비스 제공에 필요한 최소 기간만 보관한다.
- 보관 기간이 코드로 강제되는 항목은 그 값을 정본으로 삼는다 (아래 "근거" 열).
- 로그·감사 이벤트에는 자소서 본문, AI 응답, 이메일, 토큰을 넣지 않는다 (CLAUDE.md 규약).

## 코드가 강제하는 보관 기간

| 대상 | 보관 기간 | 삭제 주체 | 근거 |
|---|---|---|---|
| 감사 로그 (`audit_events`) | **90일** | 일일 크론 `api/cron/purge-deleted-users.js` → `purgeExpiredAuditEvents` | `lib/audit-log.js` `AUDIT_RETENTION_DAYS = 90` |
| 탈퇴 예약 계정 + 그 계정의 모든 데이터 | 예약 후 **30일** 유예, 이후 파기 | 같은 일일 크론 | `lib/account-deletion.js` `DELETION_GRACE_PERIOD_MS` |
| 자소서·분석 리포트 | 사용자가 삭제하거나 탈퇴 파기 시까지 | 사용자 조작 / 탈퇴 파기 | 처리방침 3조와 일치 |
| 분석 요청 레코드 (`analysis_requests`) | 계정과 수명을 같이함 | 탈퇴 파기 시 함께 삭제 | Prisma 관계 |

크론은 Vercel Cron이 `CRON_SECRET` Bearer 인증으로 매일 호출한다.

## 플랫폼이 관리하는 로그·백업 (대시보드 확인 필요)

코드로 통제할 수 없고 요금제에 따라 달라지는 항목이다. 실제 값 확인 후 아래 표를 갱신할 것.

| 대상 | 어디서 확인 | 확인된 값 |
|---|---|---|
| Supabase DB 자동 백업 보관 기간 | Supabase → Database → Backups | (확인 필요 — Free 요금제는 자동 백업 없음, Pro는 일일 백업 7일) |
| Supabase Auth 로그 | Supabase → Logs | (확인 필요) |
| Vercel 런타임 함수 로그 | Vercel → 프로젝트 → Logs | (확인 필요 — Hobby 요금제는 단기 보관) |
| Vercel 빌드 로그 | 배포별 빌드 페이지 | (확인 필요) |

**주의:** 플랫폼 로그는 요청 URL·IP 등 접속 기록을 담을 수 있으나, 애플리케이션이
자소서 본문이나 이메일을 로그로 출력하지 않으므로 민감 본문이 플랫폼 로그에 남지 않는다.

## 백업과 삭제 요청의 관계

사용자가 탈퇴(30일 유예 후 파기)해도 플랫폼 자동 백업에는 파기 이전 시점의 데이터가
백업 보관 기간만큼 남을 수 있다. 처리방침 3조의 "관계 법령에 따른 보관"과 별개로,
백업 보관 기간이 확정되면 이 문서와 처리방침에 그 사실을 반영한다.
