## 사용자 결정 사항

- 토큰 = **Claude Code 작업 토큰**(Gemini 비용·번들 성능 아님).
- 범위 = **전체**: 정리 + 클라이언트 + 서버 + 테스트 + CSS. 단계별 체크포인트 커밋.
- 스크래치 = `.superpowers/`만 git에서 제거. `docs/superpowers/`는 유지.
- grep 테스트 = **보안·단일정의 가드만 남기고 삭제**. 필요하면 렌더 테스트로 대체.
- 시작 전제 = 사용자가 진행 중인 **랜딩 캔버스 작업(index.css·Home.tsx·prerender·Home.canvas.test.tsx)을 먼저 커밋**한다. 이 계획은 깨끗한 워킹트리에서 시작한다.

## 모든 단계에 적용하는 규칙

1. **동작 보존.** 사용자에게 보이는 동작·권한·멱등성·에러 코드·응답 필드명은 바뀌지 않는다. 특히 admin 라우트의 불투명 에러 `{ error: "Request failed", requestId }`는 `tests/api/admin/security-boundary.test.js`가 보안 경계로 고정하고 있으므로 유지한다.
2. **`api/` 파일 수는 12개 그대로.** `scripts/vercel-function-limit.test.js`가 12/12를 고정. 분해는 항상 `lib/`로.
3. **단계 종료 조건** = `pnpm check` 통과 + `pnpm exec vitest run` 전체 통과(0 실패). 그 다음 체크포인트 커밋 여부를 **묻는다**.
4. **순수 이동 우선.** 한 커밋에 "파일 이동/추출"과 "로직 변경"을 섞지 않는다. 추출은 export 이름·시그니처를 그대로 옮긴다.
5. prettier는 파일 단위로만(`pnpm exec prettier --write <파일>`). 저장소 전체 포맷 금지(기존 코드가 설정을 안 따름).
6. 삭제는 **명시적 경로 하나씩**. 와일드카드·재귀 삭제 없음. `git rm`으로 추적 해제.
7. 무관한 버그를 발견하면 고치지 않고 마지막 보고에 적는다.

## 남은 위험

- **Phase 3·4는 순수 이동이라도 diff가 크다.** 각 파일 분할을 별도 커밋으로 두고 단계 경계에서 체크포인트 푸시 여부를 묻는다.
- `useIdempotentSubmit`·`useAnalysisReport` 같은 훅 추출은 두 호출자의 미세한 차이(에러 분기 5개 vs `getCompanyAnalyzeError`)를 매개변수로 흡수해야 한다. 차이를 지우지 말 것.
- `pnpm build`는 로컬 `DATABASE_URL`이 있을 때만. 없으면 Vercel 프리뷰 배포로 대체하고 못 돌린 검증은 그렇게 보고한다.
- 의존성 17개 제거 후 `pnpm install`은 락파일을 바꾼다. 이 커밋은 단독으로 둔다.
- Phase 5 CSS 분할은 캐스케이드 순서가 바뀌면 시각 회귀가 날 수 있어 `@import` 순서를 원본 줄 순서 그대로 유지한다.
