# 스크롤 주도형 리포트 미리보기 설계

## 목표

랜딩 페이지의 리포트 미리보기가 각 예시 화면을 충분히 채운 실제 리포트처럼 보이게 하고, 데스크톱 사용자가 섹션을 스크롤할 때 `첫인상`부터 `예상 질문`까지 순서대로 읽도록 만든다.

## 범위

- 변경 대상은 `client/src/components/ReportShowcase.tsx`와 그 검증 테스트다.
- API, 리포트 데이터 스키마, 실제 분석 결과 화면, 랜딩의 다른 섹션은 변경하지 않는다.
- 프리뷰는 기존 네 장(`첫인상`, `핵심 진단`, `문장 피드백`, `예상 질문`)을 유지한다.

## 스크롤 동작

- 데스크톱 넓이에서 리포트 프레임은 프리뷰 전용 스크롤 구간 동안 화면에 고정된다.
- 사용자가 페이지를 아래로 진행하면 스크롤 진행도에 맞춰 장면이 `첫인상 → 핵심 진단 → 문장 피드백 → 예상 질문` 순으로 전환된다.
- 마지막 장면을 지난 뒤에는 페이지가 다음 랜딩 섹션으로 평소처럼 이어진다. 휠 이벤트를 가로채거나 페이지 스크롤을 잠그지 않는다.
- 기존 자동 재생은 제거한다. 좌우 화살표와 목차 버튼은 계속 장면을 직접 선택할 수 있다.
- 작은 화면과 `prefers-reduced-motion: reduce` 환경에서는 고정 스크롤 연출을 사용하지 않는다. 카드 내 버튼으로 장면을 탐색하며 일반 페이지 스크롤을 유지한다.

## 화면 내용

각 장면의 검정 프레임은 현재의 최소 높이를 실제 읽을 거리로 채운다. 정보는 예시용 정적 데이터이며 실제 사용자 분석 결과처럼 보이되, 점수나 제공하지 않는 기능을 약속하지 않는다.

- 첫인상: 지원자 한 줄 인상, 키워드, 채용담당자가 기억할 모습, 근거가 된 경험, 지원자 프로필을 함께 표시한다.
- 핵심 진단: 강점과 보완점, 우선 보완 순서, 현재 포지셔닝과 목표 포지셔닝, 지원 전략 요약을 함께 표시한다.
- 문장 피드백: 더 긴 원문 문항, 최소 세 개의 하이라이트와 번호, 각 번호에 대응하는 AI 코멘트·개선 문장·잘한 점을 보여준다.
- 예상 질문: 예상 질문과 꼬리 질문, 답변에서 반드시 설명할 근거, 우선순위가 있는 액션 플랜을 표시한다.

## 구현 경계

- 장면 데이터와 프레젠테이션은 기존 `ReportShowcase.tsx` 안에 유지한다. 이 프리뷰에만 필요한 재사용 추상화나 새 의존성은 만들지 않는다.
- 프레임을 감싸는 스크롤 트랙의 진행도를 Framer Motion의 기존 스크롤 API로 읽어 활성 장면 인덱스로 변환한다.
- 장면 전환은 기존 `AnimatePresence`를 유지하되, 자동 타이머와 관련 상태 갱신은 제거한다.
- 수동으로 선택한 장면은 즉시 표시한다. 이후 사용자가 스크롤을 다시 진행하면 현재 진행도에 해당하는 장면으로 동기화된다.

## 접근성 및 반응형

- 모든 기존 버튼의 이름과 키보드 조작을 유지한다.
- 스크롤 전환은 시각적 보조 장치일 뿐, 콘텐츠를 가리거나 포커스를 강제로 이동시키지 않는다.
- 작은 화면에서는 고정 프레임과 과도한 세로 여백을 피하고, 현재와 같은 직접 탐색 UI를 유지한다.

## 검증

- `homeOnboardingCopy.test.ts`에 자동 재생이 없고 스크롤 주도 프레임의 코드 계약이 있는지 검증한다.
- 장면별 예시가 보강된 핵심 레이블과 문장 피드백의 여러 주석을 포함하는지 검증한다.
- 변경 후 대상 Vitest 테스트와 `pnpm check`를 실행한다.
