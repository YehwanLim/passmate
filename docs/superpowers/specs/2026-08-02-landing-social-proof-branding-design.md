# 랜딩 소셜 프루프 및 브랜드 표기 조정

## 목표

랜딩 페이지의 합격 기업 로고를 어두운 배경에서도 브랜드별로 식별 가능하게 만들고, 합격 기업 지표를 `20+`로 표시하며, 모든 랜딩 페이지의 브랜드 표기를 파란색 콜론을 포함한 `Pre:View`로 통일한다.

## 범위

- 다음 기업 로고 SVG만 교체하거나 다듬는다.
  - NAVER: 초록색 워드마크
  - 카카오: 노란색 워드마크
  - NHN커머스: 어두운 마키 배경에서도 읽히는 밝은 워드마크
  - 삼성전자: 더 크게 표시되는 마크
  - 현대오토에버: 더 밝은 파란색 마크
  - 현대자동차: 심볼만이 아닌 `HYUNDAI`와 `현대자동차`를 식별할 수 있는 가로형 마크
  - CJ올리브네트웍스: 여백이 큰 래스터 래퍼가 아닌 비율이 맞는 워드마크
- 크기와 정렬은 기존 소셜 프루프 데이터와 마키 CSS에서 관리한다. 원본 비율 차이가 필요한 경우에만 개별 배율을 사용한다.
- 합격 기업 지표의 원본 값을 `127`에서 `20`으로 바꾸고, 숫자와 `+`가 줄바꿈으로 분리되지 않게 한다.
- 랜딩 페이지의 `PreView` 표기를 재사용 가능한 인라인 `Pre:View` 브랜드 표기로 바꾼다. 주변 텍스트 스타일은 유지하고 콜론만 파란색으로 표시한다.
- 변경된 지표, 줄바꿈 방지, 브랜드 표기, 로고 자산 기대값을 가장 좁은 범위의 테스트로 검증한다.

## 제외 범위

- 로그인 후 제품 화면, API 동작, 후기 문구, 마키 애니메이션, 영향을 받지 않는 로고 자산은 변경하지 않는다.
- 의존성, 라우팅, 설정은 변경하지 않는다.

## 구현 개요

1. 현재 랜딩 컴포넌트에서 사용할 작은 브랜드 라벨 컴포넌트 또는 헬퍼를 추가하고, 텍스트 브랜드 표기를 교체한다.
2. 소셜 프루프 상수와 지표 마크업/CSS를 변경해 모든 브레이크포인트에서 접미사가 숫자와 함께 유지되도록 한다.
3. 영향을 받는 SVG 로고를 정리하고 필요한 경우에만 데이터 레벨의 배율을 조정한다.
4. 각 동작을 구현하기 전에 기존 컴포넌트 테스트를 확장해 실패를 확인하고, 최소 구현으로 통과시킨다.

## 검증

- 영향을 받는 SocialProof 및 랜딩 브랜드 테스트를 실행한다.
- React TypeScript 소스가 바뀌므로 `pnpm check`를 실행한다.
- 최종 diff를 확인해 명시된 랜딩·자산 파일만 변경됐는지 검토한다.

## 결정 사항

- 전역 CSS 색상 필터 대신 로고 원본 파일에 브랜드 색상을 둔다. NAVER·카카오의 인지성을 유지하면서 어두운 로고도 읽히게 하기 위함이다.
- 파란색 콜론은 이미지나 CSS 의사 요소가 아닌 의미 있는 JSX로 렌더링한다. 따라서 텍스트 선택이 가능하고 주변 타이포그래피를 그대로 상속한다.
- `white-space: nowrap`은 지표 전체가 아닌 숫자와 접미사 경계에만 적용해 반응형 카드 레이아웃을 유지한다.
