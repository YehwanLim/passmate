# 랜딩 프리렌더 설계 (2026-09-08)

## 배경

2026-09-08 랜딩 성능 2차 작업(3183d80) 이후에도 모바일 Lighthouse(시뮬 4G·CPU 4x) FCP가 5초대다.
JS는 0.35초에 다 받아지지만, 4배 느린 CPU에서 진입 JS(react-dom·framer-motion) 실행과 첫 레이아웃에
메인 스레드 1.5초가 든다. SPA는 JS가 끝나야 첫 픽셀이 나오므로 남은 병목은 "HTML이 비어 있다"는 것 자체다.

## 목표

- `/` 요청에 랜딩 본문이 채워진 HTML을 정적으로 제공해 히어로 제목이 JS 없이 그려지게 한다.
- 다른 경로(`/analyze` 등)는 지금처럼 빈 SPA 껍데기를 받는다(랜딩 본문이 잠깐 비치지 않게).
- 서버리스 함수를 추가하지 않는다(Hobby 12개 제한). 런타임 SSR이 아니라 **빌드 시점 프리렌더**다.

## 구조

| 파일 | 역할 |
| --- | --- |
| `client/src/entry-server.tsx` | `render(path)`: wouter `Router ssrPath`로 감싼 `<App />`을 `renderToString` |
| `client/src/main.tsx` | `#root`에 자식이 있으면 `hydrateRoot`, 없으면 기존 `createRoot` |
| `scripts/prerender-landing.mjs` | SSR 번들(`dist/ssr/entry-server.js`)로 `/`를 렌더해 `dist/public/index.html`의 `<div id="root"></div>`에 주입. 주입 전 원본은 `dist/public/app.html`로 저장 |
| `package.json` `build` | `vite build` → `vite build --ssr src/entry-server.tsx --outDir ../dist/ssr` → `node scripts/prerender-landing.mjs` → 기존 esbuild |
| `vercel.json` | catch-all 리라이트 목적지를 `/index.html`에서 `/app.html`로 |

Vercel은 파일시스템을 먼저 보므로 `/`는 `index.html`(프리렌더)을 받고, 나머지 비-API 경로만 리라이트로 `app.html`을 받는다.

## 동작 변화

- 히어로 제목·내비·배경은 HTML 파싱 직후 보인다. `opacity 0`에서 페이드인하는 부제·CTA·카드는 지금처럼 하이드레이션 뒤 나타난다.
- 로그인 버튼은 서버 렌더 시 `isLoading` 상태이며, 하이드레이션 후 세션에 따라 바뀐다(현재와 동일).
- `pnpm dev`는 프리렌더를 거치지 않는다. `pnpm preview`는 모든 경로에 `index.html`을 주므로 로컬 프리뷰에서만 다른 경로에 랜딩이 잠깐 비칠 수 있다. 이때 `main.tsx`는 경로가 `/`일 때만 하이드레이션하고, 아니면 `#root`를 비우고 새로 그려 하이드레이션 불일치를 피한다.
- 마퀴 로고 `<img>`는 `loading="lazy"`라 프리렌더 HTML에 preload 링크가 생기지 않는다(React 19는 즉시 로드 이미지를 preload로 올린다).

## 검증

- `client/src/entry-server.test.tsx`: `render("/")`가 제목·내비를 포함한 HTML을 콘솔 에러 없이 반환.
- `scripts/prerender-landing.test.js`: 주입 함수가 플레이스홀더를 정확히 한 번 치환하고, 없으면 throw. `vercel.json` catch-all이 `/app.html`을 가리키는지 가드.
- 빌드 후 로컬 정적 서빙 + Lighthouse(모바일)로 FCP/LCP 재측정, 프로덕션 빌드에서 콘솔 에러(하이드레이션 경고 포함) 0건 확인.

## 위험

- 서버·클라이언트 첫 렌더가 다르면 React가 경고를 내고 클라이언트에서 다시 그린다(깨지진 않지만 이득이 사라짐). 브라우저 API를 렌더 중에 읽는 컴포넌트를 랜딩에 추가하면 재발한다.
- 랜딩 컴포넌트가 import 시점에 `window`를 만지면 빌드가 실패한다. 빌드 실패는 배포 전에 드러나므로 조용한 회귀는 아니다.
