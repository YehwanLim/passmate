# 관리자 사용자별 분석 이용권 관리 설계

## 목적

관리자가 Users 영역에서 각 사용자의 남은 분석 이용권을 확인하고, 필요할 때 무료 분석 횟수를 직접 지급하거나 미리 만든 무료 이용권 쿠폰을 적용할 수 있게 한다. 그로블 결제 할인과 할인율 쿠폰은 이번 범위에서 제외한다.

## 범위

- Users 목록에 사용자별 남은 분석 이용권을 표시한다.
- 사용자 상세 화면에서 직접 무료 이용권을 지급하고 지급 이력을 확인한다.
- Users 영역에서 무료 분석 이용권 쿠폰을 생성·수정·비활성화하고, 특정 사용자에게 적용한다.
- 모든 지급과 쿠폰 적용을 서버에서 인증·인가·검증하고 감사 이력으로 보관한다.

다음은 이번 변경에 포함하지 않는다.

- 그로블의 결제 상품 또는 할인율 연동
- 사용자가 쿠폰 코드를 직접 입력·교환하는 흐름
- 이미 지급한 이용권의 회수 또는 차감

## 제공 정책

분석 이용권은 다음 세 잔액을 별도로 계산한다.

| 구분 | 출처 | 표시 | 소진 우선순위 |
| --- | --- | --- | --- |
| 기본 무료 | 계정당 기본 1회 | 무료 이용권 | 1 |
| 관리자 지급 | 직접 지급 또는 쿠폰 적용 | 관리자 지급 이용권 | 2 |
| 결제 이용권 | 그로블 결제 웹훅 | 프리미엄 이용권 | 3 |

- Users 목록에는 위 세 잔액을 합산한 `잔여 분석 이용권`을 표시한다.
- 사용자 상세의 이용권 관리 카드에는 세 잔액과 합계, 최근 지급 이력을 구분해 표시한다.
- 직접 지급은 1 이상의 정수만 허용한다. 운영 실수를 방지하기 위해 한 번에 10,000회까지 허용하며, 사유 메모는 선택 입력이다.
- 쿠폰은 코드, 무료 분석 횟수, 최대 사용 횟수(무제한 가능), 만료일(없음 가능), 활성 상태를 가진다. 할인율은 저장하거나 노출하지 않는다.
- 관리자는 활성·미만료·잔여 사용 횟수가 있는 쿠폰만 적용할 수 있다. 같은 쿠폰은 같은 사용자에게 한 번만 적용할 수 있다.
- 직접 지급과 쿠폰 적용은 모두 무료 이용권이 아니라 `관리자 지급 이용권`으로 기록한다. 따라서 기본 무료 1회와 결제분의 출처가 섞이지 않는다.

## 데이터 모델

기존 `analysis_entitlements`에 `bonus_credits_granted` 정수 컬럼(기본값 0)을 추가한다. 이는 직접 지급과 쿠폰으로 지급된 총 이용권이다. 기존 `premium_credits_granted`는 결제 웹훅만 계속 증가시킨다.

`analysis_reservation_source` enum에 `BONUS`를 추가한다. 이용권 예약은 `FREE → BONUS → PREMIUM` 순서로 생성해 무료 지급분을 결제 이용권보다 먼저 사용한다. 잔액 조회는 예약 상태가 `PENDING` 또는 `CONSUMED`인 사용량을 각 출처별로 빼서 계산한다.

새 테이블은 다음과 같다.

### `credit_coupons`

- `id`, `code`(유니크, 대문자 정규화), `credits_granted`
- `max_uses`(nullable), `used_count`, `expires_at`(nullable), `is_active`
- 생성·수정 시각

쿠폰 정의를 보관한다. `used_count`는 쿠폰 적용 성공 시에만 증가한다.

### `admin_credit_grants`

- `id`, `user_id`, `credits_granted`
- `source` (`MANUAL` 또는 `COUPON`)
- `coupon_id`(직접 지급이면 null), `note`(선택), `granted_by_user_id`
- 생성 시각

각 관리 작업을 변경 불가능한 이력으로 남긴다. `(coupon_id, user_id)`의 유니크 제약으로 동일 사용자에게 같은 쿠폰을 두 번 적용하는 것을 데이터베이스에서도 막는다.

새 Prisma 모델과 `User` 관계를 추가하고, SQL 마이그레이션은 기존 배포 방식에 맞춰 `prisma/migrations/`에 작성한다. 기존 Settings의 브라우저 저장소 기반 할인 쿠폰 데이터는 실제 지급 흐름과 연결되지 않으므로 제거하고, 쿠폰 관리는 Users 영역의 서버 데이터만 사용한다.

## 서버 경계와 흐름

관리자 전용 이용권 API와 쿠폰 API를 추가한다. 모든 엔드포인트는 기존 `requireAuthenticatedUser`로 세션을 검증한 뒤 DB의 `users.role === "admin"`을 다시 확인한다.

### 사용자 이용권 조회와 직접 지급

Users 목록은 서버가 계산한 사용자별 잔여 이용권 요약을 받아 표시한다. 사용자 상세는 동일 API로 무료·관리자 지급·프리미엄 잔액 및 최근 지급 이력을 요청한다.

직접 지급 요청은 대상 사용자 ID, 양의 이용권 수, 선택 메모만 받는다. 서버 트랜잭션 안에서 대상 사용자의 entitlement 행을 잠그고 생성한 뒤 `bonus_credits_granted`를 증가시키고, 관리자의 ID와 함께 `admin_credit_grants` 이력을 생성한다. 성공 응답은 갱신된 잔액 요약을 반환한다.

### 쿠폰 관리와 적용

쿠폰 관리 API는 쿠폰 목록 조회, 생성, 수정(지급 횟수·사용 한도·만료일·활성 상태)을 제공한다. 쿠폰 코드는 생성 후 변경하지 않는다. 이미 사용한 쿠폰의 지급 횟수를 바꾸는 것은 과거 지급 이력과 정의가 달라지는 문제를 피하기 위해 막는다. 필요한 경우 새 쿠폰을 만든다.

쿠폰 적용 요청은 사용자 ID와 쿠폰 ID만 받는다. 하나의 트랜잭션에서 쿠폰을 잠근 다음 활성 상태, 만료일, 최대 사용 횟수, 사용자별 중복 적용 여부를 확인한다. 검증을 통과하면 사용 횟수와 해당 사용자의 `bonus_credits_granted`를 증가시키고 `admin_credit_grants` 이력을 생성한다. 동시 적용으로 한도를 넘기거나 중복 지급되는 경우 전체 트랜잭션을 실패시킨다.

인증되지 않은 요청은 401, 관리자가 아닌 요청은 403, 잘못된 값은 400, 존재하지 않는 사용자·쿠폰은 404로 처리한다. 비활성·만료·한도 소진·중복 쿠폰은 409와 이해 가능한 오류 코드를 반환한다. 클라이언트는 Supabase로 잔액이나 지급 데이터를 직접 수정하지 않는다.

## 관리자 화면

### Users 목록

기존 Users 테이블에 `잔여 이용권` 열을 추가한다. 데스크톱에서 총 잔여 회수를 보여 주며, 모바일은 기존 상세 화면에서 동일 정보를 확인할 수 있게 한다. 목록의 행 선택 동작은 현재처럼 사용자 상세 화면으로 이동한다.

Users 페이지 헤더에는 `무료 이용권 쿠폰 관리` 버튼을 둔다. 대화상자에서 쿠폰을 생성·수정·비활성화하고 코드, 지급 횟수, 사용 횟수, 만료일, 상태를 확인한다.

### 사용자 상세

기존 통계 아래에 `분석 이용권 관리` 카드를 추가한다.

- 총 잔여 이용권과 기본 무료·관리자 지급·프리미엄 잔액
- 직접 지급 횟수와 사유 메모 입력, 확인 버튼
- 적용 가능한 쿠폰 선택과 적용 버튼
- 최근 지급 이력: 시각, 출처(직접 지급/쿠폰), 횟수, 쿠폰 코드, 사유, 처리 관리자

직접 지급 또는 쿠폰 적용은 제출 중 중복 클릭을 막는다. 성공하면 카드와 목록의 잔액을 새로고침하고 성공 알림을 표시한다. 실패하면 서버 메시지를 보여 주되 기존 잔액은 유지한다.

## 기존 이용권 API의 호환성

`getEntitlementSummary`는 기존 `freeRemaining`, `premiumRemaining`, `remaining`, `premiumEnabled`를 유지하고 `bonusRemaining`만 추가한다. 따라서 기존 분석 화면과 사용자 이용권 화면은 총 잔여 횟수와 결제분 표시를 계속 사용할 수 있다. 관리자 화면만 추가 필드를 사용한다.

`reserveAnalysis`는 기본 무료가 남아 있으면 `FREE`, 그다음 관리자 지급분이 남아 있으면 `BONUS`, 그렇지 않으면 `PREMIUM` 예약을 만든다. 정상 저장 시에만 예약이 `CONSUMED`가 되고, 실패·취소 시에는 기존처럼 `CANCELLED`가 된다.

## 검증 기준

- Users 목록에서 각 사용자의 서버 계산 잔여 이용권을 확인할 수 있다.
- 관리자는 대상 사용자에게 양의 횟수와 선택 메모로 이용권을 직접 지급할 수 있고, 관리자 지급 잔액과 이력이 즉시 갱신된다.
- 관리자가 생성한 무료 이용권 쿠폰은 설정한 지급 횟수, 사용 한도, 만료일, 활성 상태를 따른다.
- 같은 쿠폰은 같은 사용자에게 두 번 적용되지 않으며, 쿠폰 한도를 동시에 초과하지 않는다.
- 비관리자·비인증 사용자는 조회·지급·쿠폰 관리 API를 사용할 수 없다.
- 기존 결제 웹훅은 계속 프리미엄 이용권만 지급하고, 기존 이용권 조회 및 분석 예약/취소 동작은 보존된다.
- 무료, 관리자 지급, 프리미엄 이용권의 잔액 합계가 화면과 서버 응답에서 일치한다.
