# 사용자가 기대하는 것과 다시 오는 이유 (2026-10-05, v2)

> 목적: 개편을 실행하기 전에 두 가지를 먼저 정한다.
> ① 사용자가 Pre:View에서 **가장 기대하는 것** ② 사용자를 **계속 다시 오게 할 이유**.
> 모든 기능·가격·카피는 이 두 정의를 기준으로 판단한다.
>
> v2에서 반영한 사용자 결정(10-05):
> - 서비스 목표 = **경험을 나열 → 공고에 맞게 조합해 스토리(초안)를 만들어 줌 + 완성된 자소서를 분석함**
> - 초안까지 쓴다. 단, **부풀리지 않는 AI**로, 내가 한 것만으로 정리한다.
> - 사용자가 아직 없으니 **기능은 최소로** 간다.
> - 설문 문항은 바꾸지 않는다.

### 창업자가 25건 넘게 반복한 처방 = 이 서비스의 설계도

1. **순서 공식**: 이 직무는 이런 일을 한다 → 이런 역량이 필요하다 → 나에게 그 역량이 있다 → 이 경험이 근거다 → 입사 후 이걸 하겠다
2. **모든 경험을 한 줄 컨셉으로** 모으기
3. **경험 표**: 경험·키워드·300/500/800자 버전을 저장해 두고, 문항 키워드로 꺼내 붙이기

창업자가 사람 손으로 해 온 이 방법을 제품으로 옮기는 것이 Pre:View 목표 (1)이다. **경쟁사가 베낄 수 없는 건 기능이 아니라 이 처방이 3년, 약 140건의 실제 상담에서 나왔다는 사실이다.**

### 다시 온 사람 (12명 이상 + 후기 기준 16명)

- 다음 채용 시즌에 다시: 2명
- 그 밖에 후기에 나온 이유: 다음 회사, 고친 뒤 다시 확인

## 2. 정의 ① — 사용자가 가장 기대하는 것

> **"내가 실제로 한 경험만으로, 이 공고에 맞는 자소서를 빨리 완성하고, 내기 전에 뽑는 사람 눈으로 확인받는 것."**

| 기대 | 근거 | 제품 |
| --- | --- | --- |
| **내 경험이 이 공고에서 무엇이 되는지** 알고 싶다 | 고민 4위(22건), 막힌 곳 1·2위 | 경험 → 공고 조합 → 초안 (목표 1) |
| **빨리** 쓰고 싶다. 매번 처음부터 쓰기 싫다 | 막힌 곳 "오래 걸림", "1시간 완성"을 보고 신청 | 경험을 한 번 적어 두면 회사마다 다시 쓴다 |
| **내 것**이어야 한다. 면접에서 무너지면 안 된다 | 고민 1위 면접(38건), 티오 불만 1위 "부풀림" | **부풀리지 않는 AI** + 완성본 분석과 꼬리 질문 (목표 2) |
| 내기 전에 **확신**을 얻고 싶다 | 후기 대부분이 감정 표현으로 끝남, 탈락 불안 11건 | 분석 리포트(첫인상·고칠 곳) |

### 차별점 한 줄

> **"부풀리지 않는 AI. 내가 한 일로만, 이 공고에 맞게."**

| | 서류합격부터 | 티오 | Pre:View |
| --- | --- | --- | --- |
| 하는 일 | 점수 + 문장 수정 | 공고 → 초안 생성 | 내 경험 → 초안 → 분석 |
| 약점 | 근거 없는 합격률 | 안 한 일까지 부풀림 | — |
| 지키는 약속 | | | 경험에 없는 사실은 쓰지 않는다 |

### "부풀리지 않는다"를 눈에 보이게 하는 장치 (약속만 하면 아무도 안 믿는다)

1. **초안 문장마다 출처 표시**: 이 문장이 어느 경험에서 왔는지 보여 준다. 기업 분석의 출처 발췌(groundingSupports)와 같은 방식이다.
2. **경험에 없는 숫자·성과는 빈칸**: 지어내지 않고 `[실제 수치]`처럼 남겨 사용자가 채우게 한다.
3. **맞는 경험이 없으면 묻는다**: "이 문항에 쓸 경험이 부족해요. 이런 경험이 있나요?" 억지로 끌어다 쓰지 않는다.

## 3. 정의 ② — 다시 오게 할 이유

억지로 붙이지 않는다. 취업 준비에서 이미 생기는 반복에 맞춘다.

| 순위 | 다시 오는 순간 | 왜 Pre:View로 다시 오나 |
| --- | --- | --- |
| 1 | **새 회사에 지원할 때** | 경험이 이미 적혀 있다. 공고와 문항만 넣으면 초안이 나온다. 처음보다 훨씬 빠르다 → **경험이 쌓일수록 떠나기 어렵다** |
| 2 | **서류가 붙어 면접을 볼 때** | 내 경험으로 쓴 자소서라 꼬리 질문을 방어할 수 있다. 분석 리포트에 예상 질문이 이미 있다 |
| 3 | **고친 뒤 다시 확인할 때** | 완성본 분석 |

매일 들어오게 하는 장치는 만들지 않는다. 취준생은 마감이 있을 때 온다.

## 4. 최소 기능 범위 — 지금 만들 것과 미룰 것

**핵심 고리 하나만 완성한다.**

```
내 경험 적기  →  공고·문항 넣기  →  부풀리지 않는 초안  →  고쳐서  →  분석 리포트
 (있음)          (작업실 있음)        (★ 새로 만들 것)                 (있음)
```

| 구분 | 항목 | 이유 |
| --- | --- | --- |
| **지금** | 경험 → 초안 생성(출처 표시·빈칸·되묻기 포함) | 목표 1의 유일한 빈칸. 이게 없으면 고리가 안 이어진다 |
| 지금 | 초안 → 분석으로 바로 넘기기 | 목표 2와 연결. 이미 있는 "지난 진단으로 미리 채우기"를 재사용한다 |
| 미룸 | 시즌권·잠금 해제·가격 개편 | 사용자가 없으면 판단할 수 없다. 핵심 고리가 쓰이는지 먼저 본다 |
| 미룸 | 기업별 페이지·AI 티 검사기 | 입구 확대는 고리가 완성된 뒤에 |
| 미룸 | 면접 준비 모드·경험 자동 추천 | 재방문 2순위. 사용자가 생긴 뒤에 |
| 뺌 | 창업자 검수권, 설문 문항 교체 | 사용자 결정(10-05) |

**덤으로 생기는 입구**: 지금 /analyze는 "이미 쓴 자소서가 있는 사람"만 쓸 수 있다. 10-02 실측에서도 폼까지 와서 떠난 사람이 많았다. 경험 → 초안이 생기면 **자소서가 아직 없는 사람도 시작할 수 있다.** 기능을 늘리지 않고도 진입점이 넓어진다.

## 5. 정할 것 (다음 스펙에서)

- 초안 1회를 무료로 줄지, 이용권을 쓸지. 원가는 리포트와 비슷한 수준일 것으로 보인다(1건 약 40~100원). 사용자를 모으는 단계라 넉넉하게 주는 쪽을 권한다.
- 경험 입력 양식: 지금 "내 경험" 탭의 항목만으로 순서 공식을 채울 수 있는지 확인이 필요하다(역할·한 일·결과·배운 점).
- 초안 길이: 문항 글자 수 제한에 맞춘다. 멘토가 쓰던 300/500/800자 방식을 참고한다.
