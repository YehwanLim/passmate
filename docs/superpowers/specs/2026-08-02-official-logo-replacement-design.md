# 공식 로고 교체 설계

## 목표

사용자에게 보이는 모든 Pre:View 브랜드 표현을 제공받은 대문자 `PRE:VIEW`
워드마크로 바꾼다. 로고는 밝은 배경과 어두운 배경 모두에서 읽기 쉬워야 하며,
기존의 텍스트 렌더링 워드마크에 의존하지 않는다.

## 범위

- 제공받은 로고 이미지에서 투명 배경의 크롭된 원본 자산을 준비한다.
- 어두운 UI 표면에 사용할 흰색 워드마크 변형을 준비한다.
- `Logo`가 스타일이 적용된 텍스트 대신 적절한 자산을 렌더링하도록 바꾼다.
- 랜딩 페이지 문장과 리포트 제목 안의 사용처를 포함해 `BrandName`도 같은
  이미지 형태로 렌더링하도록 바꾼다.
- 브라우저 파비콘은 로고의 콜론 심볼로 교체한다. 전체 워드마크는 파비콘
  크기에서 읽을 수 없기 때문이다.
- 기존 공개 경로의 구형 `passmate-wordmark.png`, `passmate-logo.png`,
  `pre-view-wordmark.svg`도 새 자산을 가리키도록 유지해, 직접 URL 접근 시
  이전 PassMate 로고가 노출되지 않도록 한다.
- 이미지 대체 텍스트로 접근 가능한 `Pre:View` 이름을 유지한다.

이 작업은 PassMate를 참조하는 기존 내부 식별자, 저장소 키, API 이름, 법적
서비스 문구를 변경하지 않는다. 시각적인 공식 브랜드 표현과 이미 Pre:View로
브랜딩된 문서 제목만 교체한다.

## 자산 전략

제공받은 래스터 이미지를 시각적 기준 자산으로 사용한다. 일반 사용을 위해
워드마크 부분을 투명 캔버스에 크롭하고, 어두운 배경용으로는 글자를 흰색으로
바꾸되 콜론은 기준 이미지의 하늘색으로 유지한다. 콜론 발광은 두 점이 이어져
보이지 않을 만큼 약하게 낮춘다. 이렇게 하면 브라우저 폰트로 근사하는 대신
제공된 글자꼴과 고유한 콜론 심볼을 보존할 수 있다.

작은 파비콘에는 콜론을 별도 자산으로 내보낸다. 파란색 처리는 기준 로고의
알아볼 수 있는 특징을 유지하면서도 작은 크기에서의 가독성을 보장한다.
이전에 공개된 이미지 파일명은 호환용 별칭으로 유지하되, 워드마크는 제공 이미지
기반의 기본 자산으로, 심볼은 파란 콜론으로 대체한다.

## 컴포넌트 동작

`Logo`와 `BrandName`은 기존 호출부를 개별적으로 수정하지 않도록 브랜드 표시를
위한 단일 공개 컴포넌트로 유지한다. 각 컴포넌트는 `alt="Pre:View"`를 가진
이미지를 렌더링하고, 크기와 배치는 호출부의 클래스 이름으로 계속 제어한다.
명시적인 밝음/어두움 변형은 원본 또는 흰색 이미지를 고른다. 기존의 어두운
배경 호출부는 흰색 변형으로 옮기고, 밝은 배경의 인라인 브랜딩은 원본 변형을
사용한다.

## 검증

- 테스트에서 두 공용 브랜드 컴포넌트가 접근 가능한 이미지를 렌더링하고,
  요청된 변형을 선택하는지 먼저 검증한다.
- 로고와 브랜드명에 한정한 Vitest 테스트를 실행한다.
- TypeScript 컴포넌트 변경이므로 `pnpm check`를 실행한다.
- 변경된 자산 경로와 참조를 확인해, 공식 시각 로고가 기존 PassMate 아트워크나
  텍스트 렌더링 워드마크를 가리키는 곳이 남아 있지 않은지 점검한다.
