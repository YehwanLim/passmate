# 네이버 블로그 채용 공고 자동 발행 루틴 — 설계

작성일: 2026-09-25 · 상태: 사용자 승인(설계) → 구현 계획 대기

## 1. 목표

창업자의 네이버 블로그(`blog.naver.com/815lyw`)에 **신입·인턴 채용 공고 글**을 꾸준히 올려 네이버 검색 노출을 극대화한다.
합격·면접 후기는 사용자가 직접 쓰고, 채용 공고 글은 루틴이 **검색 → 작성 → 편집기 입력 → 임시저장 → 알림**까지 하고
**발행 버튼은 사용자가 누른다.** 글 끝에는 그 공고에 맞춘 Pre:View 진단 안내를 넣어 사이트 유입으로 잇는다.

성공 기준:

- 공고가 있는 날 밤 21시에 임시저장 글 1편이 편집기에 완성되어 있고, 푸시 알림이 온다(주 2~3편).
- 일요일에는 "이번 주 접수 중 신입 공채 모음" 1편이 같은 방식으로 준비된다.
- 같은 회사·같은 공고를 두 번 쓰지 않는다.
- 글에서 `utm_source=naverblog` 유입이 GA4에 잡힌다.

## 2. 확인된 사실(2026-09-25 시험)

- Claude 데스크톱의 Chrome 확장과 내장 브라우저는 `*.naver.com`을 안전 정책으로 차단한다. 쓸 수 없다.
- `agent-browser`(0.35, `/opt/homebrew/bin`)는 네이버를 연다. 전용 프로필 `~/.agent-browser-profiles/naver-blog`에
  사용자가 직접 로그인했고(로그인 상태 유지), 프로필이 유지되므로 다음 실행에서도 로그인이 남는다.
- 글쓰기 화면 `https://blog.naver.com/GoBlogWrite.naver` → `blog.naver.com/815lyw?Redirect=Write&`.
  편집기는 `iframe#mainFrame` 안의 스마트에디터 ONE. 접근성 트리에 본문이 노출되지 않아
  **좌표 클릭(제목 CSS 186,249 · 본문 258,360 @ 1200×646 뷰포트) + 실제 키 입력**으로 제목·본문을 넣었고,
  상단 "저장" 버튼(ref 스냅샷의 `button "저장"`)으로 임시저장이 됐다(임시저장 글 67 → 68).
- 첫 진입 시 "도움말" 패널이 열릴 수 있다. 닫기 버튼이 있으면 닫고 진행한다.
- 헤드리스로 뜬 데몬은 옵션을 바꿔도 재사용된다. 옵션을 바꾸려면 `close --all` + 데몬 종료 후 다시 띄운다.
  모든 호출은 같은 플래그(`--session naver-blog --headed --profile … --idle-timeout 0`)를 붙여야 한다 → 래퍼 스크립트로 고정.
- 네이버 블로그 글쓰기 API는 없다. 편집기 입력이 유일한 자동화 경로다.

## 4. 구성 요소

### 4.1 파일

```
.agents/blog-job-posts/
  style.md        작성 규격(제목 공식·본문 구조·금지 사항·해시태그·마무리 안내)
  ledger.md       발행 대장: 회사 | 공고명 | 접수 마감 | 작성일 | 상태(임시저장/발행/건너뜀) | 블로그 URL
  drafts/YYYY-MM-DD-<company-slug>.md   글별 초안(제목·본문·태그 원문). 입력 실패 시 수동 붙여넣기용
scripts/naver-blog.sh   agent-browser 래퍼: 세션·프로필·headed 플래그 고정 + 하위 명령(open-write, type-title, type-body, save, screenshot, check-login)
```

`.agents/`는 `product-marketing.md`처럼 커밋 대상이다(`threads-*.md`만 gitignore). 대장과 초안도 커밋해 기록을 남긴다.
초안에 자소서 본문·개인정보는 들어가지 않는다(공개 공고 정보뿐).

### 4.2 하루 흐름(21:00)

1. **상태 점검** — `scripts/naver-blog.sh check-login`: 블로그 홈에서 "로그아웃" 버튼이 보이면 로그인 상태. 아니면 "로그인 필요" 알림 후 종료.
2. **대장 갱신** — 블로그 글 목록(분류 "Career")을 읽어 대장의 `임시저장` 항목 중 발행된 것을 `발행`으로 바꾸고 URL을 적는다.
3. **공고 탐색** — 웹 검색(잡코리아·사람인·링커리어·인크루트·각 사 채용 페이지)으로 오늘 기준 접수 중이거나 7일 내 접수 시작하는
   신입·인턴 공고를 모은다. 각 후보는 **공식 채용 페이지 원문**을 열어 접수 기간·직무·자격·문항을 확인한다(2차 출처만으로 쓰지 않는다).
4. **선정** — 제외: 대장에 이미 있는 회사(같은 시즌), 마감 3일 이내, 경력직·계약직 전용, 원문 확인 실패.
   우선순위: 대기업 그룹 공채 > 채용연계형 인턴 > 중견·스타트업 신입 > 체험형 인턴. 동률이면 검색량이 클 회사명.
   후보가 없으면 "오늘은 쓸 공고 없음(검토한 후보 n개)" 알림만 보내고 종료.
5. **작성** — `style.md` 규격으로 초안 md 생성. 커버 이미지 1장은 HTML 템플릿(회사명·공채명·접수 기간 텍스트)을 agent-browser 스크린샷으로 PNG 생성.
6. **입력** — 글쓰기 화면 열기 → 도움말 닫기 → 제목 입력 → 본문 입력(문단마다 Enter) → 커버 이미지는 "사진" 업로드
   (파일 선택 대화상자 처리는 구현 계획에서 검증; 안 되면 이미지 없이 진행하고 알림에 표시) → 본문 끝 해시태그 → "저장" 클릭 → 임시저장 수 증가 확인.
7. **기록·알림** — 대장에 `임시저장` 행 추가, 초안 md 저장, 푸시 알림: 제목 + "임시저장 글 보기에서 확인 후 발행(분류: Career)".

### 4.3 일요일 흐름

단건 대신 **주간 모음** 1편. 대장의 이번 주 글 + 새로 검색한 접수 중 공고를 합쳐 10~15개를 표로(회사·직무·마감·링크).
이미 단건 글이 있는 회사는 그 글 링크를 단다. 제목 예: "10월 첫째 주 접수 중 신입 공채 모음 (9/29~10/5 마감 순)".

### 4.4 글 규격 요지(`style.md`에 전문)

- **제목**: `{회사명} {연도} {시즌} 신입 공채 채용공고 | 모집 직무·일정·자소서 문항`(50자 내, 검색어를 앞에).
- **본문 순서**: ① 한 문단 요약(누가·언제까지·무엇을) ② 핵심 정보 표(접수 기간·모집 직무·지원 자격·전형 절차·공식 링크)
  ③ 자소서 문항 원문 + 문항별 "읽는 사람이 보는 것" 2~3문장(가이드 규격 §2와 같은 관점) ④ 회사가 최근 힘주는 사업 1~2개(기사 링크)
  ⑤ 지원 시 유의점 ⑥ 마무리 안내(이 글의 문항 중 하나를 골라 어디서 막히기 쉬운지 + Pre:View 링크) ⑦ 해시태그 5~8개.
- **분량** 1,500~2,500자. 담백한 해요체. 한 문단 3~4문장.
- **금지**: 공고 전문 복사(요약+출처만), 회사 로고·공고 이미지 사용, 합격 스펙·경쟁률 추측, 점수·퍼센트, 경력직·이직 언급,
  가이드 규격의 AI 티 나는 표현 12가지, 지어낸 통계.
- **연결**: 같은 회사의 사이트 가이드(`pre-view.me/guide/...`)가 있으면 링크. 수요일 가이드 루틴이 같은 공채를 다루면 서로 링크.
- **정직성**: 기존 후기 글의 "AI로 안 썼다"는 주장과 섞이지 않도록 공고 글은 정보 글로 두고, 1인칭 경험담을 지어내지 않는다.

### 4.5 예약 작업

로컬 예약 작업(주간 SEO 회고와 같은 방식) `naver-blog-job-posting`, 매일 21:00. 프롬프트는 자체 완결형:
`style.md`·`ledger.md`·`scripts/naver-blog.sh`를 읽고 §4.2(일요일은 §4.3)를 수행. 클라우드 루틴은 이 브라우저를 못 쓰므로 쓰지 않는다.

## 5. 실패 처리

| 상황 | 처리 |
| --- | --- |
| 로그인 풀림 | 알림 "네이버 로그인 필요" + 래퍼로 로그인 창 띄우는 명령 안내. 글은 초안 md로만 저장 |
| 편집기 입력 실패(구조 변경 등) | 스크린샷 저장, 알림에 초안 md 경로 첨부 → 사용자가 붙여넣기 |
| 임시저장 수가 안 늘어남 | 1회 재시도 후 실패 알림 |
| 후보 없음 | 검토 후보 수와 함께 알림, 대장에 `건너뜀` 기록 |
| Mac 꺼짐 | 그날은 건너뜀. 다음 날 대장 갱신에서 자연 복구 |
| 이미지 업로드 불가 | 이미지 없이 저장하고 알림에 표시 |

## 6. 검증 순서

1. `scripts/naver-blog.sh`를 만들고 `check-login`·`open-write`·`type-title`·`type-body`·`save`를 이 세션에서 돌려 오늘 시험을 재현한다.
2. `style.md`·`ledger.md`를 쓰고, 실제 공고로 **단건 1편 + 주간 모음 1편**을 이 세션에서 만들어 사용자가 검수한다
   (글은 반드시 사용자 검토 후 발행).
3. 검수 반영 후 예약 작업 등록. 첫 주는 대장·알림·발행 여부를 같이 본다. 2주 뒤 네이버 서치어드바이저·GA4에서 유입을 확인해 제목 공식을 조정한다.

## 7. 남은 위험

- 좌표 클릭은 뷰포트 크기에 묶인다. 래퍼가 뷰포트를 1200×646으로 고정하고, 구현 계획에서 `.se-title-text` 포커스(JS) 방식이 되면 그쪽으로 바꾼다.
- 네이버가 자동 입력을 이상 행동으로 볼 가능성. 실제 키 입력·하루 1편·사용자 발행이라 위험은 낮지만, 캡차가 뜨면 사용자에게 넘긴다(캡차는 루틴이 풀지 않는다).
- 사용자가 임시저장 글을 오래 발행하지 않으면 마감이 지난 공고가 쌓인다. 대장 갱신 시 마감 지난 `임시저장`은 `만료`로 표시해 알림에 넣는다.
- 오늘 만든 "[테스트] 자동 입력 확인용 임시 글"은 사용자가 임시저장 목록에서 지운다.
