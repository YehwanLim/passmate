# 게스트 분석 세션 잠금 설계

## 목표

로그인하지 않은 사용자가 분석을 시작했을 때, 브라우저에 남아 있던 다른 사용자의 Supabase 세션이 분석 중 또는 분석 후에 복원되지 않게 한다. 게스트 분석 결과는 어떤 계정에도 저장하지 않으며, 로그인은 사용자가 로그인 버튼을 명시적으로 선택했을 때만 허용한다. 게스트는 같은 공인 IP에서 1년 동안 성공한 분석 1회만 실행할 수 있다.

## 문제와 원인

`AuthProvider`는 앱 마운트 후 비동기로 Supabase의 저장 세션을 복원한다. `Analyze` 화면은 이 초기화가 끝나기 전에 분석 제출을 허용한다. 따라서 사용자가 화면상 비로그인 상태에서 분석을 시작해도, 이전 세션이 늦게 복원되면 앱이 해당 계정으로 전환되고 분석 결과 저장 로직이 그 계정을 사용할 수 있다.

분석 API는 로그인 함수를 호출하지 않는다. 문제는 남아 있는 세션의 비동기 복원과 게스트 분석 의도가 경쟁하는 경로다.

## 선택한 접근

`AuthContext`에 게스트 세션 잠금 동작을 추가한다. 분석을 시작할 때 현재 인증 사용자가 없으면 다음을 수행한다.

1. 게스트 잠금을 먼저 켜서 이후에 도착하는 세션 이벤트를 무시한다.
2. Supabase의 로컬 세션을 폐기한다.
3. 인증 상태를 즉시 `user: null`, `isLoading: false`로 둔다.
4. 지연된 `INITIAL_SESSION`, `SIGNED_IN`, `TOKEN_REFRESHED`, `getSession()` 결과는 게스트 잠금 중이면 모두 비로그인 상태로 처리한다.

사용자가 로그인 버튼을 선택하면 게스트 잠금을 해제한 다음 기존 Google OAuth 흐름을 실행한다. 이미 로그인된 사용자가 분석을 시작하는 경우에는 잠금을 걸지 않으므로, 기존 저장 흐름은 유지된다.

## 게스트 IP 제한

게스트 분석 요청은 서버에서만 제한한다. Vercel이 제공하는 클라이언트 IP 헤더를 우선 사용하고, 로컬 개발에서는 직접 연결 IP를 보조 수단으로 사용한다. IP를 확인할 수 없는 요청은 제한을 우회시키지 않도록 분석을 실행하지 않는다.

원문 IP는 데이터베이스나 로그에 저장하지 않는다. 서버 환경변수 `GUEST_ANALYSIS_IP_HASH_SECRET`을 키로 한 HMAC-SHA-256 값만 저장한다. 이 비밀키는 배포 환경에서 32바이트 이상의 무작위 값으로 설정하며, 저장된 해시·에러 응답·클라이언트에는 절대 노출하지 않는다.

분석 시작 전 해당 해시에 대한 짧은 예약을 원자적으로 만든다. 이미 성공한 이력이 있거나 다른 요청이 진행 중이면 `429`와 `GUEST_ANALYSIS_LIMIT_REACHED`를 반환한다. AI 분석이 실패하면 예약을 삭제해 재시도를 허용하고, 성공하면 예약을 사용 이력으로 확정한다. 진행 중인 예약은 15분 뒤 만료되어 서버 중단으로 인한 영구 차단을 방지한다. 성공 이력은 생성 시점부터 1년 뒤 자동 만료되며, 만료된 이력은 다음 요청에서 제거되어 다시 1회 분석할 수 있다.

로그인된 요청은 검증된 Bearer 토큰으로 구분한다. 이 IP 제한은 게스트에만 적용하며, 로그인된 사용자의 분석 권한 정책은 변경하지 않는다.

## 게스트 리포트 게이트

게스트는 첫인상 영역을 본 뒤 핵심 진단부터 흐림 처리된 리포트와 Google 로그인 버튼을 본다. 현재 `ReportAccessGate`의 동작을 유지하며, IP 제한 추가로 공개 리포트 범위를 줄이거나 로그인 버튼 위치를 바꾸지 않는다.

## 구현 경계

- `client/src/contexts/AuthContext.tsx`
  - 게스트 잠금 상태를 Provider 수명 동안 유지한다.
  - 세션 이벤트와 초기 `getSession()` 결과를 잠금 상태에 맞춰 정규화한다.
  - `lockGuestSession()`을 Context 값으로 제공한다.
  - 명시적 Google 로그인 전에 잠금을 해제한다.
- `client/src/types/auth.ts`
  - `AuthState`에 게스트 잠금 메서드를 선언한다.
- `client/src/pages/Analyze.tsx`
  - 분석 시작 시 사용자가 없으면 분석 API 요청 전에 게스트 잠금을 완료한다.
  - 로그인된 요청에는 현재 세션의 Bearer 토큰을 함께 보낸다.
  - 로그인된 사용자의 저장·분석 흐름은 바꾸지 않는다.
- `lib/guest-analysis-limit.js`
  - 신뢰할 수 있는 요청 IP 선택, HMAC 생성, 15분 예약, 1년 사용 이력 확정을 담당한다.
- `api/analyze.js`와 `vite.config.ts`
  - 서버리스와 로컬 개발 분석 경로 모두에서 동일한 게스트 제한을 실행한다.
- `prisma/schema.prisma` 및 새 마이그레이션
  - 해시, 상태, 예약 만료, 사용 만료만 보관하는 게스트 제한 테이블을 추가한다.
- `client/src/pages/Privacy.tsx`
  - 해시된 IP 사용 이력의 부정 이용 방지 목적과 최대 1년 보관을 명시한다.

기존 로그인 유지 정책은 변경하지 않는다. 게스트 세션 잠금은 사용자가 게스트 분석을 선택한 현재 앱 세션에만 적용된다.

## 오류 처리

로컬 세션 폐기 요청이 오류를 반환해도 분석은 중단하지 않는다. 잠금은 이미 먼저 적용되어 있으므로, 이후 세션 이벤트는 비로그인으로 처리한다. 오류는 진단용 경고로만 남긴다. IP 해시 비밀키가 없거나 요청 IP를 안전하게 식별할 수 없으면 분석을 실행하지 않고 설정 오류를 반환한다.

## 검증

- 게스트 잠금 상태에서 지연된 Supabase 세션이 도착해도 `user`를 설정하지 않고 로컬 로그아웃을 다시 요청하는지 테스트한다.
- 게스트 사용자가 분석을 시작하면 API 호출 전에 잠금 메서드를 기다리는지 테스트한다.
- 명시적 Google 로그인은 잠금을 해제한 후 기존 OAuth 옵션으로 실행되는지 테스트한다.
- 같은 게스트 IP의 첫 성공 요청만 허용하고, 두 번째 요청은 AI 호출 전에 `429`로 거절하는지 테스트한다.
- 실패한 분석의 예약과 15분 넘은 예약을 해제해 재시도를 허용하는지 테스트한다.
- 로그인된 Bearer 요청은 게스트 IP 제한을 소비하지 않는지 테스트한다.
- 게스트 리포트가 핵심 진단부터 로그인 버튼으로 잠기는 기존 동작을 테스트한다.
- 관련 Vitest 테스트, 타입 검사, 프로덕션 빌드를 실행한다.

## 범위 확인

- 미결 항목, 임시 표기, 모호한 요구사항 없음.
- 게스트 분석, 기존 명시적 로그인, 게스트 IP 사용 이력 사이의 인증·사용량 경계만 다룬다.
- 게스트 분석이 결과를 계정에 저장하지 않는 기존 조건(`user?.id && user.email`)을 유지한다.
