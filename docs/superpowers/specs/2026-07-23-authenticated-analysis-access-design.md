# 로그인 기반 자소서 분석 접근 설계

## 목적

비로그인 사용자는 자소서 분석을 시작할 수 없도록 하고, 로그인 완료 뒤 원래 의도한 분석 화면으로 자연스럽게 복귀시킨다. 로그인한 사용자는 별도 결제 없이 무료 분석을 이용할 수 있다는 점을 로그인 화면에서 명확히 안내한다.

## 범위

- 비로그인 상태에서 홈·랜딩·마이페이지 등의 분석 CTA를 누르거나 `/analyze` 주소에 직접 접근하면 로그인 화면으로 보낸다.
- 로그인 성공 후 `/analyze`로 복귀한다.
- 로그인 화면에 `로그인만 하면 무료로 자소서 분석을 시작할 수 있어요.` 안내를 표시한다.
- 브라우저 화면 보호에만 의존하지 않고, 분석 API도 인증된 요청만 허용한다.

기존 게스트 분석·게스트 IP 제한 계획은 이 정책과 충돌하므로 이번 동작의 대상이 아니다.

## 설계

### 클라이언트 접근 제어

`Analyze`는 기존 인증 컨텍스트의 세션 로딩이 끝난 뒤 인증되지 않은 경우 `/login?redirect=/analyze`로 이동한다. 이 규칙은 CTA가 어디에 있든 최종 목적지인 `/analyze`에서 적용되므로 주소 직접 입력에도 우회되지 않는다.

세션 판별 중에는 분석 입력 폼과 실행 버튼을 렌더링하지 않고 간단한 로딩 상태만 보인다. 따라서 인증이 아직 복원되지 않은 순간에 비로그인 사용자가 입력하거나 분석 요청을 시작할 수 없다.

인증 가드는 현재 `useRequireAuth`의 재사용 가능한 형태로 확장한다. 분석 화면은 복귀 경로를 `/analyze`로 지정하고, 기존 마이페이지 등의 보호 경로는 현 동작을 유지한다.

### 로그인 경험과 문구

`Login`은 기존의 안전한 `redirect` 검증을 계속 사용한다. Google OAuth의 콜백 URL도 동일한 `redirect`를 보존하므로, 로그인 완료 시 자동으로 분석 화면으로 이동한다.

로그인 카드의 설명에는 다음 문구를 포함한다.

> 로그인만 하면 무료로 자소서 분석을 시작할 수 있어요.

문구는 로그인 CTA 바로 위의 설명 영역에 배치해, 분석을 시도하다 온 사용자가 무료 이용 조건을 한눈에 이해하게 한다.

### 서버 측 분석 인증

`Analyze`의 분석 요청은 현재 로그인 세션의 access token을 `Authorization: Bearer <token>` 헤더로 전달한다. `/api/analyze`는 기존 `requireAuthenticatedUser` 유틸리티로 토큰을 검증하고, 사용자가 없거나 토큰이 유효하지 않으면 AI 호출 전에 `401 Unauthorized`를 반환한다.

클라이언트는 `401` 응답을 받으면 `/login?redirect=/analyze`로 이동한다. 이미 열린 화면에서 세션이 만료되어도 분석 결과나 AI 사용량을 노출하지 않는 방식이다. 그 외 분석 오류의 기존 메시지 처리와 글자 수 검증은 유지한다.

## 오류 처리

- 인증 초기화 중: 분석 폼을 숨기고 로딩 상태만 표시한다.
- 비로그인 진입 또는 만료된 세션: 로그인 화면으로 보내며 `/analyze` 복귀 경로를 보존한다.
- 누락·위조된 API 토큰: API가 401을 반환하고 AI 모델은 호출하지 않는다.
- OAuth 로그인 실패: 기존 로그인 오류 메시지를 그대로 보여 준다.

## 검증

- 비로그인으로 `/analyze`에 접근하면 `/login?redirect=/analyze`로 이동한다.
- 로그인 후에는 `/analyze`로 돌아와 분석 폼을 볼 수 있다.
- 로그인 화면에 무료 분석 안내 문구가 보인다.
- 클라이언트 분석 요청에 access token이 포함된다.
- 토큰이 없는 `/api/analyze` POST는 401을 반환하며 모델 호출 전에 중단된다.
- 기존 로그인 사용자 분석 흐름과 분석 오류 메시지 테스트는 계속 통과한다.
